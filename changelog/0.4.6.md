# launchme 0.4.6

Released 2026-10-31.

## New
- **Windows installer** (`launchme-<version>-win64-setup.exe`, thanks to @Drackrath, #16): per user by default
  (no administrator prompt, `%LOCALAPPDATA%\Programs\Launchme`), a Start menu entry and an uninstaller in
  Settings → Apps; *Install for all users* (or `/ALLUSERS`) installs into Program Files and updates through the
  next Setup run elevated. The ZIP stays for those who prefer no installer. Releases are now built on GitHub's
  runners, with the assets' `SHA256SUMS` (signed by Sigstore from the next release on).
- **Discord server**: https://discord.gg/y2wk3kr9wW
- **Flip-model presentation** (Windows): the window draws into a DXGI flip-model swap chain on the launcher's
  own Direct3D 11 device instead of an HWND render target. In full-screen Tryb TV the display can show its
  frames without a composition copy (independent flip): one frame less of latency and less GPU work. A frame
  is drawn once the previous one is on its way (frame latency 1). `LAUNCHME_SWAPCHAIN=0` draws as before.
- **Game videos decoded on the GPU** (Windows): frames go from the GPU's video decoder straight into a texture
  the renderer draws, nothing copied through memory. On Linux FFmpeg decodes with VA-API where the system has
  it. `LAUNCHME_VIDEO_GPU=0` (Windows) and `LAUNCHME_VIDEO_HWACCEL=0` (Linux) turn it off.
- **Artwork compression (BC1)** (Settings → System → Performance → *Artwork compression (BC1)*, now on by
  default and no longer only under *Low memory mode*): covers, posters and thumbnails take 8× less graphics
  memory, logos 4× (BC3); in Low memory mode backgrounds too. A better encoder (least-squares and
  principal-axis fits). Compressed pictures are kept on disk (`%LOCALAPPDATA%\Launchme\textures`, up to
  512 MB), so each one is decoded and compressed once. On Linux BC1 too, where the GPU samples it.

## Changes
- **Behind a game**: 3 s after a game came in front, the launcher runs at below-normal priority with EcoQoS
  (Windows 11: efficiency cores, low clocks) and a low memory priority, ticks 10 times a second, draws
  nothing, stops its video and gives the GPU driver's caches back; without Low memory mode it also empties
  its working set. The Guide overlay or the launcher in front restores everything at once. Prefetching the
  library's artwork runs at background CPU and disk priority.
- **Fewer wake-ups on a still screen**: without input or motion the launcher ticks at 60 Hz after 3 s and at
  30 Hz after 20 s (120–240 Hz screens wake it up to 8× less); any input or motion brings the full rate back
  with the next frame.
- Direct2D's own texture cache is bounded (160 MB, 64 MB in Low memory mode), and what the previous screens
  left unused for 10 s is released when the screen changes.
- The companion's local embedding model is loaded only while it is used and released after 3 minutes
  without use; its digest is checked once a run; ONNX Runtime keeps no memory arena between sentences.
- The artwork kept in RAM outside Low memory mode: 128 → 64 MB (read again from disk when needed).
- Background jobs reuse threads (up to 4 wait 10 s for the next job) instead of starting one per job.
- launchme.exe uses the segment heap (Windows 10 2004+) and is built with link-time code generation;
  profile-guided optimization is available to builds (`-DLAUNCHME_PGO=instrument`, then `optimize`).
